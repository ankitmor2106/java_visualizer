1. Packages & Imports

A Package in Java is a mechanism to encapsulate a group of classes, sub-packages, and interfaces. It prevents naming conflicts, controls access levels, and makes searching/locating classes easier.

package com.visualizer;
import java.util.List;

2. Classes & Objects

A Class is a blueprint or template that defines state and behavior. An Object is a physical instance of that blueprint allocated in the Heap memory at runtime.

class Car { String color; } 
Car myCar = new Car(); // 'myCar' is the reference to the object
Read official Object docs ↗

3. Constructors

A Constructor initializes newly created objects. It is invoked automatically when an object is instantiated using the new keyword. It must share the exact name of the Class and cannot have a return type.

Read official Constructor docs ↗

4. Types of Variables

Java is statically and strongly typed. Memory is handled differently based on the type:

  • Primitives: Store the exact literal value directly in memory (usually the Stack). Examples: int, double, boolean, char.
  • References: Store the memory address (pointer) of an object located in the Heap. Examples: String, Arrays, custom Classes.
Read official Data Types docs ↗

5. Methods & Scope

A Method is a collection of statements grouped together to perform an operation. Variables declared inside a method have local scope, meaning their lifecycle is tied exactly to that method's execution frame on the Call Stack.

Read official Method docs ↗

6. Access Modifiers

Modifiers define the visibility and security level of classes, fields, and methods:

  • public: Accessible from any other class in any package.
  • private: Accessible only within the exact class it is declared in.
  • protected: Accessible within the same package and by subclasses.
  • default (package-private): Accessible only within the same package.
Read official Access Modifier docs ↗

7. Core OOP Concepts

  • Inheritance: Creating new classes built upon existing ones using the extends keyword to promote code reuse.
  • Polymorphism: The ability of a single object or method to take on many forms (via overloading or overriding).
  • Encapsulation: Hiding internal data state and requiring all interaction to occur through public getter/setter methods.
Read official OOP Concepts docs ↗

8. The Call Stack

The Stack is a Last-In-First-Out (LIFO) memory structure. Every time a method is called, a new "frame" is pushed onto the stack containing its local variables and primitive data. When the method finishes, its frame is instantly destroyed.

Read official JVM Stack docs ↗

9. The Heap

The Heap is the dynamic, globally shared memory area where all Java objects and arrays are allocated at runtime. Unlike the Stack, objects in the Heap can outlive the method that created them.

Read official JVM Heap docs ↗

10. Garbage Collection (GC)

Java automatically manages memory. The Garbage Collector is a background process that monitors the Heap. If an object has zero active references pointing to it from the Stack (making it "unreachable" or "orphaned"), the GC will automatically delete it to free up memory.

Read official Garbage Collection docs ↗

11. Pass-by-Value (References)

Java is strictly pass-by-value. However, when passing an object to a method, you are passing the value of the reference (the memory address). This means the method can modify the original object's data in the Heap, but it cannot change where the original variable points.
